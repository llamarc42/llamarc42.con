# CI and review audit

This audit consolidates the fork's accepted validation requirements. It covers
the active workflows, command runner, manifest/lock checks, test inventories,
packaging/smoke evidence, review policy, and supported merge command. It does not
claim a security proof of arbitrary PR code or add product tool integrations.

## Requirement and evidence map

| Requirement                                    | Implementation and verification                                                                                                                                                                                                     |
| ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Every PR to main receives validation           | Fixed workflow path and unfiltered PR trigger checked in preflight; missing/renamed workflow and event/path mutations rejected.                                                                                                     |
| Cheap checks precede expensive checks          | Exact preflight → static → platform dependencies; ordered mandatory commands, bounded jobs and cancellation of obsolete runs.                                                                                                       |
| Windows, macOS and Linux are required          | Exact native runner matrix, literal fail-fast, both OS-specific smoke conditions, and all six actual CI jobs checked at merge time.                                                                                                 |
| A failed, skipped or omitted stage cannot pass | Job/step conditions and ignored failures checked; summary code and dependency input fixed to the reviewed implementation; its behavior exercised for every stage and non-success state.                                             |
| Required commands cannot quietly disappear     | Explicit formatter, workflow lint, contract tests, validator tests, static, desktop suites, package and smoke commands. Check order is validated.                                                                                   |
| Tests actually execute                         | Fresh JSON reports for Jest/Vitest, passing inventory and zero failures; Node passing-count floor. Negative empty/skipped report tests. The count floor is a baseline, not a requirement to update a number after every added test. |
| Diagnostics survive ordinary test failure      | Test report artifacts use a narrowly allowed always-run upload step; missing reports before tests start are allowed, never counted as passing tests. Cancellation may prevent upload; Actions logs remain primary evidence.         |
| PR-controlled installs receive no credentials  | Removed token environment. Pinned public ripgrep assets are downloaded directly and hash-checked before the existing package consumes its cache. No authenticated download code is needed.                                          |
| Dependency definitions remain consistent       | Both manifest and lock-only changes, including deletion, checked; actual builds use npm ci. Root comparison is not a full npm dependency-graph verifier.                                                                            |
| Build the code being reviewed                  | Checkout ref overrides and retained credentials rejected; current-head CI and expected native jobs required. Reviewed head must contain current main before merge.                                                                  |
| Copilot completes before merge                 | Current-head verified reviewer and non-dismissed submitted review, unresolved threads, latest successful agent run; known incomplete-review notices rejected. Read summary-only findings manually.                                  |
| API errors cannot authorize the merge command  | Every metadata failure aborts before merge; regression injection at each read. No cached green status is used. Newer failed CI cannot fall back to an older green run.                                                              |
| Merge remains a user decision                  | Default command is read-only. Explicitly authorized --merge uses GitHub's expected-head SHA and never admin bypass or auto-merge.                                                                                                   |

## Consolidated corrections

The audit fixes credential propagation to npm, a replaceable/no-op summary
checker, incomplete preflight command/dependency/trigger coverage, lack of
failure-report artifacts, stale-base acceptance, missing actual platform jobs at
merge time, and acceptance of a Copilot timeout summary. The metadata relay now
recognizes the observed `Running Copilot Code Review` workflow name as well.

Regression coverage includes mutations to workflow structure, commands, ordering,
credentials, check inputs and checker body; actual checker execution; invalid
test inventories; lock-only changes; and merge API failure scenarios. The real
locked Windows ripgrep downloader was also exercised against the verified cache
without credentials. Full native matrix execution remains the integration check
after this consolidated commit.

## Explicit limits and disposition rules

- These repository validators protect against accidental weakening. A PR can
  also edit its validators/tests, so they are not an independent security boundary.
  Making them impossible to alter would require trusted external enforcement,
  not an ever-growing list of syntax prohibitions. Review CI changes as code.
- Required repository rules are still a bootstrap task. This PR does not enable
  rulesets, merge itself, publish a release, or change upstream. Until then,
  the supported agent merge path provides checks, not universal UI enforcement.
- GitHub statuses cannot expire or be revoked during a total API outage. They
  are advisory. The live merge command blocks on unavailable data; administrators
  can still bypass that command. Expected-head matching is atomic for the head,
  not for concurrent base/review changes; repository rules remain necessary.
- Hosted review-run identity is verified against the currently observed dynamic
  Copilot path. If GitHub changes it, the command blocks pending a reviewed update.
  Automated code cannot judge whether every prose suggestion was substantively
  addressed. Read the entire review, including summary-only findings.
- The supported desktop inventory excludes live provider credentials and retains
  documented upstream skips. CLI/JetBrains/binary/Rust changes need additional
  lanes. Packaging on three runners does not establish all distribution targets.
- Do not treat every new suggestion as mandatory. Fix violations of the above
  requirements; record evidence for false positives; document platform limits.
  Optional refactoring or hypothetical tamper-proofing is not a merge blocker
  solely because a reviewer proposes it.

Further review findings should be mapped to this table and handled in one batch.
Do not promise that a nondeterministic reviewer will never find another issue.
